PROJECT / 01Installed, personal project

JAT Cipherline 2300

Network security and Linux infrastructure

JAT Cipherline 2300 is my home lab on a Proxmox server in Bangladesh. I manage it from Cardiff and use it to learn about VPNs, Linux, private services and running systems that other people depend on.

Proxmox VEUbuntuVPNTailscaleLinuxDockerTraefik
Read more

What I built

The lab runs on an HP mini PC and brings together a VPN gateway, security monitoring, a Kali Linux virtual machine and private services such as Nextcloud, Vaultwarden and Pi-hole. I also worked on a management console for monitoring connections and managing the lab.

The VPN is used by my family for remote connectivity. I've worked on individual accounts, devices and access to the home network.

What I learned

One of the hardest parts has been making changes without interrupting services. I've broken working configurations before and had to troubleshoot remote access, which made testing, backup planning and recovery much more important to me.

I use an AI coding assistant to help with scripts and research. I review changes and test them against the equipment I manage.

Evidence and limits

The gateway and services installation scripts were supplied for private review, and I have reported the system as installed in November 2026. It has had no independent audit or penetration test.

Private gateway-backup evidence (21 November 2026) showed that an archive was readable and that the console SQLite database passed integrity checks. It did not contain Nextcloud user files or Proxmox VM disks, and no isolated restore has been performed. The backup itself remains private. The sanitised backup review explains its limits.

PROJECT / 02Home lab, reported active

Home Security Operations Centre

Security monitoring and detection

I use Wazuh to collect and investigate events in my lab and Splunk to look at activity through dashboards. I have also written detection rules for the VPN, firewall, console and other services.

WazuhSplunkCustom detection rulesLog analysisPythonSuricata
Read more

What I work on

I have written custom Wazuh rules for authentication failures, firewall blocks, VPN sessions and other lab events. I also worked on getting useful log data from my TP Link router and reducing unnecessary alerts.

A problem I solved

A router authentication message was matching a general Wazuh rule instead of the rule I wanted. I investigated the way the rules were processed and changed the rule structure so that the router event was identified correctly.

Evidence and limits

My Wazuh decoders, rules and router Mail Log receiver are available in the public detection code. The encrypted router log receiver is still being rolled out, and Suricata is not running continuously. This is a personal lab and has not been independently assessed.
